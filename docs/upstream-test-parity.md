# Upstream test parity

Every test function in upstream [`webrtc-rs/rtc`](https://github.com/webrtc-rs/rtc) (master) and
[`webrtc-rs/webrtc`](https://github.com/webrtc-rs/webrtc) v0.17.1 (the top-level crate and its
sub-crates) has, in this fork, a test of the same name in the corresponding crate, or a row here:

- **mapped**: the fork tests the same behaviour under other names (the last column names them;
  each must exist).
- **excluded**: the test cannot exist here, and why. Almost all of these test I/O the sans-I/O
  engine does not have: sockets and the virtual network (`vnet`), async streams, tasks and
  timers, the UDP mux, gatherers, detached channels, the operations queue, the TURN server. The
  environment (`tests/testenv_*.rs`, run by `scripts/test-env/run.sh`) tests what vnet's simulated
  NATs did, on real ones.
- **port**: the test applies to this engine and is not there yet; the row names the stream that
  ports it. `scripts/check-test-parity.py` fails while any `port` row remains.

The upstream names are committed in [`upstream-tests/`](upstream-tests/) (one
`fork crate, upstream file, test` line each; regenerate with
`python3 scripts/check-test-parity.py --generate <rtc checkout> <webrtc v0.17.1 checkout>`).
`scripts/check-test-parity.py` (the `Test inventory` job in `cargo.yml`) checks that every
upstream test is accounted for, that every mapped name is a fork test, and that no row is stale
(a row for a test that has gained a same-named fork test, or that upstream no longer has, fails).
Crate `.` is the fork's top-level `rtci` crate (`src/`, `tests/`); upstream's `webrtc` crate maps
to it, and its sub-crates to the `rtci-*` crate of the same protocol (`data` to `rtci-datachannel`,
`util` to `rtci-shared`).

Judgements per test, written down: when a mapping is coarse (one fork test covering several
upstream ones), the fork test still has to fail if the behaviour breaks.
