# RFC 8839 conformance audit: SDP offer/answer procedures for ICE

Spec: RFC 8839, "Session Description Protocol (SDP) Offer/Answer Procedures for Interactive
Connectivity Establishment (ICE)", January 2021 (current; obsoletes RFC 5245 together with
RFC 8445, and RFC 6336).

Audited at fork master 8916bc3. Code: `src/peer_connection/sdp/mod.rs`,
`src/peer_connection/mod.rs`, `src/peer_connection/internal.rs`,
`src/peer_connection/transport/ice/`, `rtci-ice/src/candidate/mod.rs` (`marshal`,
`unmarshal_candidate`), `rtci-ice/src/agent/mod.rs`, `rtci-sdp/src/description/`. Sections 4, 5, 6
and 9 are done clause by clause. Sections 7 and 8 (SIP, ALGs: 16 keyword clauses) bind a SIP user
agent, not this engine; they are one `n/a` row each.

Level `MUST*` marks a requirement stated without a BCP 14 keyword; it is counted as MUST.

Context that shapes many verdicts: the engine writes JSEP descriptions (RFC 9429). Every `m=`
line is port 9 with `c=IN IP4 0.0.0.0`, before and after nomination; at the audit there was one
ICE transport (BUNDLE was required, decision D2 in `docs/conformance.md`; since mt-2 each section
outside a BUNDLE group, and each group, has a transport and ICE agent of its own); a description without ICE is refused
rather than handled by plain RFC 3264 (RFC 9429 section 5.10 requires that), so the "fall back
to RFC 3264" clauses are `n/a`.

## Gaps, in order of importance

1. **Tolerant candidate parsing** (5.1-5 violated, 5.1-3, 5.1-11 partial). Size S. In
   `extract_ice_details` and `add_remote_candidate`, skip (log, do not fail) a candidate line with
   an FQDN other than `<uuid>.local`, an unknown transport or an unknown type; scan every
   extension pair for `tcptype`; check `typ`, foundation and priority range.
2. **`ice2` and `ice-pacing`** (4.2.1.5-1, 4.3.1-3, 4.3.2-3 missing; 4.2.1.5-2, 4.3.1-4, 4.3.2-4,
   5.5-1 missing). Size S for `a=ice-options:trickle ice2` (also for a lite agent: `ice2` alone)
   and reading the peer's `ice2`; size M for `ice-pacing` (write it, read it, pace checks by the
   larger value), which depends on RFC 8445 Ta pacing existing in the agent.
3. **Component handling** (5.1-6 partial). Size S. Write component 1 only (rtcp-mux is
   required), and give the agent only remote candidates of component 1.
4. **Answer transport protocol** (4.3.2-6 violated). Size S. Copy the offer's `m=` proto into
   the answer (`TCP/DTLS/SCTP`, `TCP/TLS/RTP/SAVPF`), as RFC 9429 section 5.3.1 also requires.
5. **Checks before the answer** (4.2.4-1 partial). Size M. Before remote credentials are known,
   answer a Binding request whose USERNAME starts with the local ufrag and whose
   MESSAGE-INTEGRITY verifies with the local password, and remember it as a triggered check.
6. **Credential validation on the sending side** (5.4-5, 5.4-6, 4.4.1.1.1-3, 4.4.2.1-2 partial).
   Size S. Validate application-supplied credentials with the receive-side rule (4..=32 and
   22..=256 ice-chars); on a restart never reuse them.
7. **Related address privacy** (5.1-10 missing, 5.1-8 partial). Size M. Keep a candidate's base
   apart from the `raddr` / `rport` it signals, so the signalled pair can be `0.0.0.0 9`; refuse
   a local srflx / relay candidate without a related address.
8. **Default destination and nomination in SDP** (4.2.1.2-2 partial; 4.2.1.2-3, 4.3.4-1, 4.3.4-2,
   4.4.1.2.2-1, 4.4.1.2.2-3, 4.4.1.3-3, 4.4.1.3-4, 5.2-1 missing; 4.4.1.2.2-2 violated). Size L.
   Fill `c=` / `m=` with the default candidate, then with the nominated one; write
   `remote-candidates`; decide whether later offers list only the nominated candidate (RFC 8839)
   or all (RFC 9429 and browsers), and record the decision in `docs/conformance.md`.
9. **`remote-candidates` on receipt, lite subsequent offers** (4.4.2-2, 4.4.2-3, 4.4.2-4,
   4.4.2.2-1, 4.4.2.2-2, 4.4.1.3-2 missing). Size M.
10. **`ice-mismatch`** (4.2.5-4, 4.3.3-2, 5.3-2 missing; 4.2.5-1 MAY missing) and **rejecting a
    non-restart offer that changes `ice-lite` / `ice-options`** (4.4.2.1-6). Size S each; for
    `ice-mismatch` a WebRTC endpoint can only fail the description, which should be the decision
    recorded.
11. **Candidates per `m=` section** (4.2.1.2-1, 4.3.1-1, 4.3.2-1 partial; 4.2.1.6-2 partial).
    Size S: record as a consequence of D2 (BUNDLE only), and stop writing candidates into a
    section that then gets port 0.
12. **Tests for behaviour that holds by construction** (the 17 `untested` MUST rows). Size M.

  `src/peer_connection/sdp/mod.rs:1899`. Reproduce: apply a remote offer whose first section has
  `a=candidate:1 1 udp 2130706431 host.example.com 5000 typ host` (or `... typ host` with
  transport `dccp`, or `typ foo`) beside a valid candidate; `set_remote_description` returns
  `ErrAddressParseFailed` instead of ignoring the line.
- **B2: the answer's `m=` protocol is always UDP** (4.3.2-6).
  `rtci-sdp/src/description/media.rs:131`, `src/peer_connection/sdp/mod.rs:836`. Reproduce: offer
  `m=application 9 TCP/DTLS/SCTP webrtc-datachannel`; the answer says `UDP/DTLS/SCTP`.

  `src/peer_connection/sdp/mod.rs:793-799`. Reproduce: one host candidate, a data-channel-only

  has one component and rtcp-mux is required for media.
