# RFC 5104: Codec Control Messages in the RTP Audio-Visual Profile with Feedback (AVPF)

Spec: RFC 5104, February 2008 (updated by RFC 7728 and RFC 8082, which do not change the clauses
below). Audited against fork master 8916bc3. Scope: 3.5.3 and 3.5.4 (the normative statements inside
the "motivation" section), 4.2 (TMMBR, TMMBN), 4.3 (FIR, TSTR, TSTN, VBCM), 5, 7. Mixer and translator
clauses (4.x.x.4) are `n/a`: the engine is an endpoint.

What exists:

- **FIR**: wire codec `rtci-rtcp/src/payload_feedbacks/full_intra_request/mod.rs`; `ccm fir` is in the
  default video feedback list (`src/peer_connection/configuration/media_engine.rs:407`); inbound FIR is
  delivered to the application by `KeyFrameRequestInterceptor` (`rtci-interceptor/src/keyframe.rs:58`,
  in the default interceptor set) and counted in `firCount`
  (`src/statistics/accumulator/rtcp_reports.rs:112`, `:199`). The engine never originates a FIR: the
  application builds one and calls `RTCRtpReceiver::write_rtcp`.
- **TMMBR, TMMBN, TSTR, TSTN, VBCM**: nothing. No codec (FMT 3/4 of RTPFB and FMT 5/6/7 of PSFB parse
  into `RawPacket` at `rtci-rtcp/src/packet.rs:125`, `:132`), no SDP parameter is offered, no behaviour.
  None of them is in `docs/conformance.md` "Not implemented, on purpose".

## Gaps, in order of importance

1. **TMMBR / TMMBN (L).** IDs 4.2.1-1 through 4.2.2.3-1, 5-2, 7.1-2, 7.2-5 (27 rows). Wire codecs for
   RTPFB FMT 3 and 4 (S on their own); the bounding-set algorithm of 3.5.4.2, TMMBN generation and the
   `2*RTT + T_Dither_Max` hold-off on the sender side; saving TMMBNs and deciding when to request on
   the receiver side; `ccm tmmbr [smaxpr=]` in SDP; a way to hand the resulting ceiling to the
   application's encoder and to the congestion controller. This is not optional for a WebRTC
   endpoint: RFC 8834 5.1.6 says endpoints that send media are REQUIRED to implement TMMBR and MUST
   follow the limit a TMMBR sets for their SSRC (sending TMMBR is OPTIONAL). The minimum that meets
   it: the two codecs, `ccm tmmbr` in the default video feedback, the sender-side bounding set and
   TMMBN, and the ceiling exposed to the application and the estimator. It is absent from
   `docs/conformance.md` in every form, the "Not implemented, on purpose" table included.
2. **TSTR / TSTN and VBCM (M, low value).** IDs 4.3.2-1 through 4.3.4.2-2 (16 rows). Codecs for PSFB
   FMT 5, 6, 7 and delivery to the application; the acknowledgement rules (TSTN echoing the highest
   Seq nr) can live in a small interceptor. No browser negotiates these; list them under "Not
   implemented, on purpose" if they are not going to be built.
3. **FIR hygiene (S).** IDs 4.3.1-1, 4.3.1.2-1, 4.3.1.2-3, 4.3.1.1-2, 7.2-3, 7.2-4: reject a FIR with no
   FCI entry on both paths; write 0 as the header's media SSRC (or document the field as "must be 0");
   offer a per-(source, target) sequence counter so applications do not each reinvent it; deliver a
   FIR only when one of its FCI SSRCs is a local sender and drop repetitions of the last Seq nr; tie
   the `ccm fir` capability to the presence of `KeyFrameRequestInterceptor`.
4. **Tests (S).** IDs 4.3.1.1-5, 7.2-1, 7.2-2.

## Bugs found

1. **A FIR with no FCI entry can be marshalled.**
   `rtci-rtcp/src/payload_feedbacks/full_intra_request/mod.rs:92`: `FullIntraRequest { fir: vec![] }`
   marshals to a 12-octet packet with `length = 2`. RFC 5104 4.3.1 requires at least one entry, and the
   crate's own `unmarshal` (`:129`) rejects those bytes as `PacketTooShort`, which fails every other
   RTCP packet in the same datagram at the peer if it parses as strictly. Reproduce: marshal the value
   above, feed the bytes to `rtcp::packet::unmarshal`; expect either a marshal error or a parse, get
   `Ok` then `Err`.
2. **`ccm fir` can be negotiated with nothing behind it.** `MediaEngine::register_default_codecs` puts
   `ccm fir` (and `nack pli`) on every video codec, independently of whether
   `configure_key_frame_requests` is in the chain. Reproduce: `register_default_codecs()` plus
   `Registry::new().build()`; negotiate with a peer, send a FIR to the engine; `poll_read` never
   returns it (`noop.rs::inbound_rtcp_does_not_reach_the_application` is the behaviour), although the
   answer said `a=rtcp-fb:96 ccm fir`.

## Status after `conf/rtcp-codec` (rtci-rtcp)

- Bug 1 fixed: a FIR with no entry is not marshalled; the header's media SSRC is written as 0.
- The wire codecs of gaps 1 and 2 exist: TMMBR, TMMBN, TSTR, TSTN, VBCM (and LRR, PSFB FMT 10, for
  av1-rtp.md AV1RTP-8.2-1). Everything behind them is still open: SDP `ccm` parameters, the TMMBR bounding
  set and TMMBN generation, delivery to the application, the TSTN / VBCM acknowledgement rules.
