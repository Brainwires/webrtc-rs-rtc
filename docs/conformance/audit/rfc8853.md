# RFC 8853: Using Simulcast in SDP and RTP Sessions: clause audit

Spec: RFC 8853, January 2021. Audited at fork master 8916bc3.

What the engine does: a sender with several encodings that all have a rid writes `a=rid:<id> send` per
encoding and `a=simulcast:send a;b;c` (`~` for an inactive encoding). A remote description's `a=rid`
and `a=simulcast` are read by `get_rids` only when a local description is generated from it: the answer
mirrors each offered rid with the opposite direction. Nothing in `set_remote_description` reads rids, so
what a remote answer accepted, dropped or paused is never applied to the sender. Receivers route by the
RtpStreamId / RepairedRtpStreamId header extensions.

Path legend: `sdp/mod.rs` = `src/peer_connection/sdp/mod.rs`, `pc/` = `src/peer_connection/`,
`icpt` = `src/peer_connection/handler/interceptor.rs`.

## Gaps, in order of importance

1. **Apply the answer to the sender (M).** RFC8853-5.3.3-1, 5.3.3-2, 5.3.3-4, 5.3.3-6, 5.2-11: read the
   remote answer's `a=simulcast` / `a=rid`; deactivate encodings whose rid was dropped or paused; fall
   back to a single stream when the answer has no `a=simulcast`.
2. **Pause marks without RFC 7728 (S, or M with RFC 7728).** RFC8853-5.2-9, 5.3.2-9, 5.3.3-5, 5.2-10:
   either stop writing `~` (inactive encodings simply are not listed as paused) or implement
   `ccm pause` signalling.
3. **Validation (S).** RFC8853-5.3.2-2 (several lines), 5.2-5 (direction mismatch), 5.1-1 (rid syntax),
   5.3.2-8.
4. **SDES RtpStreamId / RepairedRtpStreamId items (M).** RFC8853-5.5-2 (with rfc8851.md 4-1, 4-2).
5. **Stamp the rid extension on send (M).** RFC8853-5.5-1.
6. **Offer to receive simulcast; decline layers; alternatives (M).** RFC8853-5.3.1-2, 5.3.2-7, 5.2-7, 5.2-6.

## Bugs found

- **RFC8853-5.3.3-1:** a remote answer that drops simulcast is not honoured. Reproduce: offer three send
  rids; apply an answer with the `a=simulcast` and `a=rid` lines removed; `write_rtp` still accepts and
  sends packets for all three encodings.
- **RFC8853-5.3.2-2:** an offer with two `a=simulcast` lines in one section is answered with simulcast
  built from the second line (`src/peer_connection/sdp/mod.rs:606`).
- **RFC8853-5.2-9:** `a=simulcast:send a;~b` is written when encoding `b` is inactive, with no
  `a=rtcp-fb ... ccm pause` in the section (`sdp/mod.rs:1278`).
- **RFC8853-5.2-5:** `a=rid:q recv` together with `a=simulcast:send q` is accepted; the simulcast
  direction token is ignored (`sdp/mod.rs:635`).
