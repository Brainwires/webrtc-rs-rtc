# RFC 9429: JavaScript Session Establishment Protocol (JSEP): clause audit

Spec: RFC 9429, April 2024 (obsoletes RFC 8829; the code's comments still cite RFC 8829 and
draft-ietf-rtcweb-jsep-24 in places). Audited at fork master 8916bc3. Scope: sections 3 to 8; section 7
(examples) and the appendices carry no clause. The engine is the layer under a W3C-style API, so
promise / event-loop wording is read as "the call returns the error / emits the event".

Path legend: `pc/` = `src/peer_connection/`, `sdp/mod.rs` = `src/peer_connection/sdp/mod.rs`,
`me.rs` = `src/peer_connection/configuration/media_engine.rs`, `rtci-sdp/` = `rtci-sdp/src/`.
Lower-case requirements that describe required SDP content (the attribute lists of 5.2.1 and 5.3.1, the
checks of 5.8 to 5.11) are listed at MUST level. A verdict of `tested` names a test whose assertion I
read or whose flow cannot pass without the behaviour; everything else implemented is `untested`.

## Bugs found

- **RFC9429-5.2.2-1 / 5.3.2-1: session-version does not increment.** `update_sdp_origin`
  (`src/peer_connection/sdp/mod.rs:2359`) does `d.origin.session_version += 1` on a description whose
  version is the clock's sub-second nanoseconds. Reproduce: `create_offer` twice on one connection,
  parse both `o=` lines, assert `v2 == v1 + 1`; today v2 is unrelated to v1 and may be lower. (Also: a
  first version of 0 is taken as "not stored yet".)

  `generate_matched_sdp` (`src/peer_connection/internal.rs:597`) uses `attribute("group")`. Reproduce:
  offer with `a=group:LS 0 1` then `a=group:BUNDLE 0 1 2`; the answer has `m=... 0` for mid 2 and
  `a=group:BUNDLE 0 1`.

  without `a=group:BUNDLE`; assert the answer's m= port is 9.

  (`src/peer_connection/transport/dtls/role.rs:148`) scans media sections only (and takes the first one
