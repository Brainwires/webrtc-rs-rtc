# RFC 5077 conformance audit: TLS session resumption without server-side state (tickets), as DTLS 1.2 uses it

Spec: RFC 5077, January 2008. One row per normative sentence, plus rows marked "(proc)" for procedure the RFC states without a keyword. Written with the implementation (`conf/ice-12-dtls12-resumption`). Code: `rtci-dtls/src/resumption.rs`, `rtci-dtls/src/flight/{flight1,flight3,flight4,flight4b,flight5,flight5b,flight6}.rs`, `rtci-dtls/src/handshake/handshake_message_new_session_ticket.rs`, `rtci-dtls/src/dtls13/psk.rs` (`TicketIssuer::seal_dtls12`, `open_dtls12`), `rtci-dtls/src/session.rs`. Tests are in `rtci-dtls/src/resumption/resumption_test.rs` unless a path is given.
RFC 9846 (TLS 1.3, July 2026) obsoletes RFC 5077; the rows keep RFC 5077's section numbers, the ticket mechanism DTLS 1.2 uses.

A DTLS 1.2 server issues tickets when configured to (`ConfigBuilder::with_session_tickets`, any count above 0); a client asks for them when it has a session store (`with_session_store`). The peer connection of the `rtci` crate configures neither (`the_engine_neither_offers_nor_accepts_a_dtls12_resumption`). Interop: OpenSSL 3.5.4 (`s_client -dtls1_2 -sess_out/-sess_in`, `s_server -dtls1_2`), both roles, resumed (`Reused`) with tickets and, with `-no_ticket`, by session id.
