# RFC 7496: Additional Policies for the Partially Reliable SCTP Extension

Spec: RFC 7496, April 2015 (Proposed Standard). Audited against fork master 8916bc3 (`docs/conformance-audit` worktree), read-only.

RFC 7496, Additional Policies for the Partially Reliable SCTP Extension, April 2015. Two policies:
Limited Retransmissions (what WebRTC `maxRetransmits` maps to) and Priority. The first is implemented
and tested; the second is not implemented. Section 4 is informational.

Totals (10 clauses):

- `MUST: tested 5 / untested 0 / partial 0 / missing 0 / violated 0 / n-a 1`
- `SHOULD: tested 0 / untested 0 / partial 0 / missing 0 / violated 0 / n-a 0`
- `MAY: tested 2 / untested 0 / partial 0 / missing 1 / violated 0 / n-a 1`

Levels: MUST covers MUST / MUST NOT / SHALL / REQUIRED and procedure steps the RFC words in
lower case ("must", field definitions); SHOULD covers SHOULD / SHOULD NOT / RECOMMENDED; MAY covers
MAY / OPTIONAL, each counted as a feature. Code paths are relative to `rtci-sctp/src/`; tests are
function names in that crate. `untested` with the note "by construction" means the code cannot do
otherwise but nothing would fail if it started to.

## Gaps, in order of importance

1. **Tests for the retransmission-event side effects (S).** Assert cwnd / ssthresh / RTO backoff when a
   `Rexmit` message is abandoned at T3-rtx and at fast retransmit (RFC7496-3.1-3), and a finite
   `max_t3_rtx_retrans` with a `Rexmit 0` stream (RFC7496-3.1-6).
2. **Priority policy (M, optional).** Needs a bounded send buffer per association, a per-message
   priority and an abandonment pass on a full buffer. Closes RFC7496-3.2-1, 3.2-2. Nothing in the
   WebRTC set asks for it.
3. **Abandoned-message counters (S, optional).** `abandoned_sent` / `abandoned_unsent` per stream and
   per association (section 4.3, 4.4) would let an application or a statistics report see what
   partial reliability dropped.

## Bugs found

None specific to this RFC. The lifetime bug that also concerns partial reliability is in `rfc3758.md`
