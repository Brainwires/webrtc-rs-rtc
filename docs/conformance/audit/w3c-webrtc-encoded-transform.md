# W3C WebRTC Encoded Transform (webrtc-encoded-transform): feature-level audit

Spec: WebRTC Encoded Transform, W3C Editor's Draft of 25 June 2026 (https://w3c.github.io/webrtc-encoded-transform/; sections as numbered there). Engine: fork master 8916bc3.

Scope. The API puts a transform between encoder and packetizer on the sender and between depacketizer and decoder on the receiver. In this engine both boundaries are the application's: it packetizes with the `rtci-rtp` payloaders (or its own) and calls `RTCRtpSender::write_rtp`, and it receives `RTCMessage::RtpPacket` and depacketizes. So each row asks whether the engine gives an application what it needs to build that step, not whether the JS object exists. Streams, workers, structured cloning and promises are `n/a`.

## Gaps, in order of importance

1. **SFrame in the engine (L).** Done as the standalone `rtci-sframe` crate (see rfc9605.md): the cipher suites, the encryptor / decryptor with its key store and the three error kinds. Left: `ENCTRANS-3-2` as a transform a sender or receiver takes, `ENCTRANS-3-3`.
2. **SFrame RTP packetization and its negotiation (M).** `ENCTRANS-2.1-1`, `ENCTRANS-2.1-2`, `ENCTRANS-2.2-1`, `ENCTRANS-5-2`, `ENCTRANS-2.1.1-7`: the SFrame RTP payload format (per-frame and per-packet), its SDP signalling, a per-transceiver flag, and a format-agnostic payloader for encrypted frames.
3. **Absolute capture time and dependency descriptor (M each).** `ENCTRANS-2.1.1-1`, `ENCTRANS-4.1-6`, `ENCTRANS-4.1-7`, `ENCTRANS-4.2-1`, `ENCTRANS-4.2-2`: the two header extensions, parse and write. Done in pc-20 (`RTCRtpReceiver::encoded_frame_metadata`, `send_key_frame_request`, `OnKeyFrameRequest`, `write_rtp_with_audio_level`).
4. **Per-frame metadata for a receiver (S to M).** `ENCTRANS-4.1-5` (arrival time on `RTCMessage::RtpPacket`), `ENCTRANS-4.2-3`, `ENCTRANS-4.2-4`, `ENCTRANS-4.3-1` (width, height, layer indices, key-frame flag from every depacketizer), `ENCTRANS-4.3-3` (one frame per spatial layer). Done in pc-20 (`RTCRtpReceiver::encoded_frame_metadata`, `send_key_frame_request`, `OnKeyFrameRequest`, `write_rtp_with_audio_level`).
5. **Key frame request path (S).** `ENCTRANS-6.4-1` (SSRC to RID helper), `ENCTRANS-6.5-3`, `ENCTRANS-6.5-4` (an rtc-to-rtc test: receiver writes PLI, sender's application reads it). Done in pc-20 (`RTCRtpReceiver::encoded_frame_metadata`, `send_key_frame_request`, `OnKeyFrameRequest`, `write_rtp_with_audio_level`).
6. **Tests (S).** `ENCTRANS-4.1-3`, `ENCTRANS-4.4-2`, `ENCTRANS-4.4-3`. Done in pc-20 (`RTCRtpReceiver::encoded_frame_metadata`, `send_key_frame_request`, `OnKeyFrameRequest`, `write_rtp_with_audio_level`).
