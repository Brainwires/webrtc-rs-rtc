# RFC 8851: RTP Payload Format Restrictions (a=rid): clause audit

Spec: RFC 8851, January 2021. Errata (rfc-editor.org, 2026-11-27): 7132 (Verified 2022-10-13, section 10)
corrects the rid-id ABNF to `1*255(alpha-numeric)`, "consistent with the rules for the
RtpStreamId/RepairedRtpStreamId SDES from RFC 8852 section 3" (RFC 8851 as published also allows `-` and
`_`, of any length); the rows read section 10 with it (`conf/rid-1`). 8833 (Reported, section 8.2.2) corrects
the restriction's name "max-bps" to "max-br" (no row changes: the rows and the engine use `max-br`).
Audited at fork master 8916bc3.

What the engine does: `SimulcastRid::try_from` (`src/peer_connection/sdp/mod.rs:1321`) splits the value
on single spaces into id, direction and "the rest", and stores the rest as one string with its spaces
removed. Nothing ever reads that string. Generated `a=rid` lines are `<id> send` or `<id> recv` with no
restrictions. So the engine uses `a=rid` purely as a name for a simulcast encoding; the restriction
framework of sections 5 and 6 (pt=, max-width, max-height, max-fps, max-fs, max-br, max-pps, max-bpp,
depend) is not implemented in either direction.

Path legend: `sdp/mod.rs` = `src/peer_connection/sdp/mod.rs`, `pc/` = `src/peer_connection/`,
`icpt` = `src/peer_connection/handler/interceptor.rs`.

## Gaps, in order of importance

1. **Decide the claim (decision).** The engine implements "rid as a simulcast stream name", not RFC 8851's
   restrictions. Either list the restriction framework under "Not implemented, on purpose" in
   docs/conformance.md (it is the common browser subset), or do packages 2 to 4.
2. **Parse and echo restrictions (M).** RFC8851-10-2, 10-3, 6.3-4, 6.2.2-2, 6.2.2-3, 6.3-6, 6.2.2-6,
   5-1, 6.1-4: a typed rid with `pt=` and restrictions; answer with the offered restrictions (or drop
   the line); expose a remote `recv` rid's restrictions on the sender's encoding parameters.
3. **Validate (S).** RFC8851-10-1, 6.2.2-4, 6.2.2-5: rid-id characters, duplicates discarded entirely.
4. **Process the answer (M).** RFC8851-6.4-1 (with rfc8853.md gap 1).
5. **RtpStreamId on send and in SDES (M).** RFC8851-4-1, 4-2, 4-3 (with rfc8853.md gaps 4, 5).

## Bugs found

- **RFC8851-6.3-4:** restrictions are dropped from the answer. Reproduce: offer
  `a=rid:h send pt=96;max-width=1280;max-height=720`; the answer has `a=rid:h recv`.
- **RFC8851-10-2:** `SimulcastRid.params` loses its separators: `pt=96 max-br=1000` (two tokens) becomes
  `pt=96max-br=1000` (`let params = split.collect()`, `src/peer_connection/sdp/mod.rs:1334`). Dead data
  today, wrong the day it is used.
- **RFC8851-6.2.2-4:** two `a=rid:q send` lines: both must be discarded; the first is kept
  (`sdp/mod.rs:669`).
- **RFC8851-6.2.2-1:** `a=rid:q SEND` is accepted (`SimulcastDirection::try_from` lower-cases).
