# Draft-work register: contradictions and what the maintainers last decided

Owner rule (2026-11-27): "Go off the draft work to solve the contradictions". Where a
published specification contradicts itself or another specification, the engine's default and
the audit's wording follow the current draft work of the people who maintain it: the W3C
editor's draft and its merged pull requests and issue resolutions (candidate corrections
included), IETF "bis" Internet-Drafts and the working group's tracker, RFC errata. Where no
draft work exists, the entry says so. `audit/RULES.md` ("Contradictions") states the rule; this
file is the register, re-checked before each release (`docs/releasing.md`, "Before").
Every defect found in a specification, these contradictions included, is listed in [spec-issues.md](spec-issues.md).

  Not changed here.

  and the WPT say. Nothing open upstream; the setting gives the WPT form.

## Re-checking

Before a release (`docs/releasing.md`), for each row: fetch the editor's draft, its
`amendments.json` and the issues and PRs named, the errata list and the datatracker; update
the dates; a row whose draft work moved is either changed in the engine (tests first, the old
form kept as a setting where cheap) or re-dated here with the reason it stays.
